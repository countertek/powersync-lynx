T1 — Response assembly sits beside the transport seam, not behind each adapter

Strong

Files: src/sync/transport/{NativeHttpFetch,LynxFetchModule,HostFetch}.ts, response.ts, events.ts, bytes.ts, src/sync/LynxRemote.ts.

Problem: the three SyncStreamTransport adapters are shallow; the reader choice lives in response.ts behind a five-flag mini-protocol (WireFetchSuccess), and the ordering invariant "enterEarlyCapture() before native emits" is called in two places because no module owns it. HostFetch still sniffs lynxExtension.streamingId.

Solution: each adapter returns a finished Response; one internal syncStreamResponse accepts exactly two shapes ({bytes} | {streamingId}); NativeHttpFetch alone owns early capture; LynxRemote stops calling it.

Benefits: locality — a streamingId bug is fixed in one adapter; leverage — tests already cross SyncStreamTransport.fetch (27 + 6 tests) and survive unchanged; the transport dir becomes lintable again.

T2 — LynxFetchModule streaming fallback: a seam with no reachable second adapter

Worth exploring

Files: LynxFetchModule.ts, events.ts (64 pre-slotted LynxFetchModuleStreamingEventN, _events.get monkeypatch, foreignListeners, streamingReaderFallback), response.ts (streamingFallback), ~9 tests.

Problem: after B+C every Autolink NativePowerSyncModule on Android has httpFetch, so lynx-fetch-module can win a streaming request only when the SQL Native Module is absent — and then no database can open. The nameless-slot machinery serves an unreachable path. liveStreamNames is consulted but never populated. LynxFetchModule is still the live Android JSON adapter.

Solution: grill "LynxFetchModule is the Android JSON adapter; it never streams", record ADR-0004, delete the streaming half (pre-slots, _events hook, streamingFallback, enableFetchAPIStandardStreaming), retire the matching tests.

Benefits: events.ts collapses from three concepts to one (streamingId → reader). Less interface to learn before touching /sync/stream.

N1 — Android copies the sync-HTTP policy instead of consuming it

Strong

Files: shared/sync_http_policy.h vs IdleCompleteHttp.java:25–29, StreamingHttp.java:29–31, NativeSyncHttp.java:30.

Problem: 2500 / 30000 / 120000 / "NativePowerSyncHttpStream" re-typed in Java "in lockstep"; nothing fails on drift. iOS includes the header.

Solution: first an equality check in make test; then generate the Java constants from the header or route heuristics through the existing JNI.

N2 — Incomplete-UTF-8 hold implemented three times

Strong

Files: StreamingHttp.java:147, StreamingHttp.mm:15, bytes.ts:18. Android's comment cites the JS copy — the seam points the wrong way.

Solution: one shared C helper for iOS/Android (JS copy stays for host-fetch bodies) plus a split-multibyte case in the shared fixture catalog so all three are pinned to the same bytes.

N3 — One stream-session contract for Android and iOS NativeSyncHttp

Worth exploring

Problem: two orchestrations agree on fixtures but differ at the edges — pre-headers failure is {ok:false,message} on Android vs {ok:false,status:-1,body,idleComplete:false,…} on iOS (NativeSyncHttp.mm:152–157); abort ownership differs; Android instrumentation lacks error-then-end/abort.

Solution: keep host I/O per platform; extract the decision state machine (headers-sent, idle-vs-streaming, terminal emission, abort-after-headers) as shared C++ or as one shared behavioural test list. Stays a sub-interface (ADR-0003).

Top recommendation

T1 first — it is where the hot spots are, it deepens the three adapters without moving the seam A placed, it removes the duplicated early-capture invariant, and it lets the transport directory back under lint. Grill T2 alongside: deleting the nameless-slot fallback is what lets events.ts collapse to one concept. Native: N1 + N2 are the cheapest Strong items; N3 needs a grilling decision first.

Order: T1 → T2 (grill, ADR-0004, delete) → N1 + N2 → T3 → N3 (grill) → N4, T4 when they bite.
